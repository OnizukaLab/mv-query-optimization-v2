# TimeDependentOptimizer の ILP 定式化

このファイルで実装されている時刻依存型マテリアライズドビュー選択問題の整数線形計画法（ILP）について、目的関数と制約を詳しく説明します。

---

## 変数定義

### 決定変数
- **`y[i,j,t]`** ∈ {0,1}: タイムステップ `t` でクエリ `i` が MV `j` を使用するか
- **`z[j,t]`** ∈ {0,1}: タイムステップ `t` で MV `j` が存在するか（マテリアライズされているか）
- **`c[j,t]`** ∈ {0,1}: タイムステップ `t` で MV `j` が新規作成されるか
- **`a[j,t,k]`** ∈ {0,1}: タイムステップ `t` で MV `j` を作成する際にレシピ `k` を使用するか

### パラメータ
- **`I`**: クエリ数
- **`J`**: MV候補数
- **`T`**: タイムステップ数
- **`u_ij[i][j]`**: クエリ `i` が MV `j` を使用したときの利得（benefit）
- **`freq[t][i]`**: タイムステップ `t` におけるクエリ `i` の実行頻度
- **`b_j[j]`**: MV `j` のストレージサイズ
- **`B_max`**: ストレージ予算
- **`X[j][u]`**: 包含行列（MV `j` が MV `u` を包含する場合1）
- **`recipes[j][k]`**: MV `j` のレシピ `k` の内容 `(依存MV集合, コスト)`

---

## 目的関数（最小化）

```python
minimize: workload_cost + migration_cost
```

### 1. ワークロードコスト（負の利得）
```
workload_cost = -Σ_{t,i,j} u_ij[i][j] × freq[t][i] × y[i,j,t]
```
- **意味**: 各タイムステップで、クエリが MV を使用することで得られる利得の合計に負号をつけたもの
- **目的**: 利得を最大化する（負号により最小化問題に変換）
- **重み**: クエリ頻度 `freq[t][i]` により、高頻度クエリの最適化を優先

### 2. マイグレーションコスト
```
migration_cost = Σ_{t,j,k} cost[j][k] × a[j,t,k]
```
- **意味**: 各タイムステップで MV を作成する際のレシピコストの合計
- **目的**: MV 作成コストを最小化
- **レシピ**: 既存 MV を利用した作成（低コスト）またはフル作成（高コスト）

---

## 制約条件

### 1. 使用にはマテリアライゼーションが必要
```python
y[i,j,t] <= z[j,t]  ∀i,j,t
```
- **意味**: クエリが MV を使用するには、その MV が存在している必要がある
- **制約数**: `I × J × T`

---

### 2. 包含・重複排除制約（Inclusion/Overlap Exclusion）
```python
y[i,j,t] + Σ_{u≠j} (y[i,u,t] × X[j][u]) <= 1  ∀i,j,t
```
- **意味**: あるクエリが MV `j` を使用している場合、`j` を包含する他の MV `u` を同時に使用できない
- **目的**: 冗長な MV 使用を防ぐ
- **重要**: 分母の `/J` は削除済み（不要）、`u ≠ j` で自己包含を除外
- **制約数**: `I × J × T`

---

### 3. ストレージ予算制約
```python
Σ_j (b_j[j] × z[j,t]) <= B_max  ∀t
```
- **意味**: 各タイムステップで、マテリアライズされた MV の合計サイズがストレージ予算以内
- **制約数**: `T`

---

### 4. 作成フラグの定義

#### 初期タイムステップ（t=0）
```python
c[j,0] = z[j,0]  ∀j
```
- **意味**: 初期タイムステップでは、MV が存在すれば作成されたことになる

#### 以降のタイムステップ（t>0）
```python
c[j,t] >= z[j,t] - z[j,t-1]  ∀j,t>0
c[j,t] <= z[j,t]             ∀j,t>0
c[j,t] <= 1 - z[j,t-1]       ∀j,t>0  (追加制約)
```
- **意味**:
  - 1行目: MV が新規に存在する場合、作成フラグが立つ
  - 2行目: MV が存在しない場合、作成フラグは立たない
  - 3行目: 前のタイムステップで既に存在していれば、作成フラグは立たない（継続とみなす）
- **制約数**: `J × (T-1) × 3`

---

### 5. レシピ選択制約
```python
Σ_k a[j,t,k] = c[j,t]  ∀j,t
```
- **意味**: MV を作成する場合、必ず1つのレシピを選択する
- **制約数**: `J × T`

---

### 6. レシピ有効化制約（追加制約）
```python
a[j,t,k] <= c[j,t]  ∀j,t,k
```
- **意味**: レシピを使用できるのは、作成フラグが立っているときのみ
- **目的**: 論理的整合性の強化
- **制約数**: `Σ_j (レシピ数[j]) × T`

---

### 7. レシピ依存制約

#### 初期タイムステップ（t=0）
```python
a[j,0,k] = 0  ∀j,k (ただし recipe[k] が空でない場合)
```
- **意味**: 初期タイムステップでは、他の MV に依存するレシピは使用できない（依存先が存在しないため）
- **制約数**: `Σ_j (非空レシピ数[j])`

#### 以降のタイムステップ（t>0）
```python
a[j,t,k] <= z[dep,t-1]  ∀j,t,k, ∀dep ∈ recipe[k]
```
- **意味**: レシピ `k` を使用するには、そのレシピが依存する全ての MV `dep` が前のタイムステップで存在している必要がある
- **制約数**: `Σ_{j,t,k} |dependencies[j][k]|`

---

## コメントアウトされた制約

### クエリあたり最大1つのMV制約（不要）
```python
# Σ_j y[i,j,t] <= 1  ∀i,t  (コメントアウト済み)
```
- **理由**: 包含排除制約（制約2）により、冗長な MV 使用は既に防がれているため不要
- **削除による影響**: なし（他の制約で十分カバー）

---

## 制約数の見積もり

| 制約種類 | 数式 | 概算 |
|---------|------|------|
| 使用⇒マテリアライゼーション | `I × J × T` | 9 × 51 × 2 = 918 |
| 包含排除 | `I × J × T` | 9 × 51 × 2 = 918 |
| ストレージ予算 | `T` | 2 |
| 作成フラグ定義 | `J + J × (T-1) × 3` | 51 + 51 × 1 × 3 = 204 |
| レシピ選択 | `J × T` | 51 × 2 = 102 |
| レシピ有効化 | `Σ_j レシピ数[j] × T` | ~500 |
| レシピ依存 | `Σ_{j,t,k} |deps|` | ~1000 |
| **合計** | | **~3644** |

## まとめ

### 最適化の目的
1. **ワークロードコストの最小化**: 高頻度クエリの実行コストを削減
2. **マイグレーションコストの最小化**: MV 作成コストを抑える
3. **ストレージ予算の遵守**: 限られたストレージ内で最適化

### 主要な特徴
- **時間変化対応**: タイムステップごとに異なるワークロードに適応
- **マイグレーション考慮**: MV の作成・維持・削除のコストを明示的に考慮
- **レシピベース作成**: 既存 MV を利用した効率的な MV 作成
- **包含関係処理**: 冗長な MV 使用を排除

この定式化により、時間経過に伴うワークロード変化に対して、マイグレーションコストとクエリ実行コストのバランスを取りながら、最適な MV 選択を実現します。
