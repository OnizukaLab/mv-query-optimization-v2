# 変更サマリ（2026-04-11）

## 目的
- SQL書き換えの同値性と安全性を改善する

- ディスク枯渇調査後の再発要因を減らす

## 1. JOIN条件抽出と補完の改善

### 1-1. `JOIN ... ON` 由来の等値結合を抽出対象に追加
- 変更先: `experiments/small_test_ver2/mv_generation/original_sql_join_extractor.py`
- 変更内容:
  - `WHERE` だけでなく `JOIN ... ON` からも `alias.col = alias.col` を抽出
  - quoted identifier（`"a"."b"`）対応
  - `FROM` 抽出を `WHERE` 非依存に改善
- 理由:
  - 元SQLが ANSI JOIN 形式の場合、`WHERE` だけ見ると結合条件を見落とすため

### 1-2. JOIN補完時の「補いすぎ」抑制
- 変更先: `experiments/small_test_ver2/mv_generation/enhanced_mv_generator.py`
- 変更内容:
  - `covered_aliases` 判定を「式中に出現」ではなく「異なるエイリアス同士の比較があるか」で判定
  - 例: `t.id = 10` は非結合、`t.id = mi.movie_id` は結合として扱う
- 理由:
  - 単一テーブルのフィルタを誤って結合済み扱いしていたため

### 1-3. 回帰テスト追加
- 追加先:
  - `tests/unit/test_original_sql_join_extractor.py`
  - `tests/unit/test_join_supplement_condition_detection.py`
- 理由:
  - 抽出漏れ/補完誤判定の再発防止

## 3. 最適化モデルの高速化（疎化）

### 3-1. `LocalILPOptimizer` の疎化
- 変更先: `experiments/small_test_ver2/core/local_ilp_optimizer.py`
- 変更内容:
  - `y[i,j,t]` は `u_ij[i][j] > 0` の組だけ生成
  - 未生成 `y` は `_get_y` で 0 扱い
  - usage / inclusive 制約を疎な `y` 前提に変更
  - 目的関数 workload 項も `u_ij>0` ペアのみで和を構成
  - overlap 和は `X[j][u] != 0` の項のみ加算
  - `c[j,t]` は `CONTINUOUS [0,1]`（実装済み）
- 理由:
  - 0利得ペア・0係数項を落としてモデルサイズと係数構築コストを削減

### 3-2. Step1（UtilityOptimizerV2系）への横展開
- 変更先: `src/optimization/base.py`
- 変更内容:
  - candidate経路で `y` を疎生成
  - 目的関数を `y.keys()` ベースの疎和へ変更
  - 解復元時に未生成 `y` を 0 扱い
- 理由:
  - WSTローカルのみでなく、初期解生成フェーズでも同じ削減効果を得る

### 3-3. Step4（全時刻最適化）への横展開
- 変更先: `experiments/small_test_ver2/core/time_dependent_optimizer.py`
- 変更内容:
  - `y` 疎生成（`u_ij>0` のみ）
  - usage / inclusive / objective の疎化
  - overlap 和を `X[j][u] != 0` のみへ
  - `c[j,t]` を `CONTINUOUS [0,1]` に変更
- 理由:
  - 全時刻ILPでも変数数と制約構築負荷を削減
