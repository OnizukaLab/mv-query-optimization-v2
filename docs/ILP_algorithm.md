# ILPベースのマテリアライズドビュー選択アルゴリズム

このドキュメントでは、3つの異なる初期化戦略を持つILPベースのマテリアライズドビュー選択アルゴリズムについて説明します。これらのアルゴリズムは、クエリの総実行コストを削減するために、どのサブクエリを実体化（マテリアライズ）するかを決定することを目的としています。

各アルゴリズムは、主に以下のステップで構成されます。

1.  **初期化フェーズ (`initialize` 関数):** マテリアライズドビューの初期候補セットを選択します。戦略はファイルごとに異なります。
2.  **反復的改善フェーズ (`proposed` 関数):**
    *   **近傍探索 (`neighbor_search` 関数):** 現在のマテリアライズドビュー候補の近傍（クエリプランにおける親ノードや子ノードなど）を探索し、候補セットを拡張します。
    *   **候補のフィルタリング:** 拡張された候補セットから、実際に利得をもたらす可能性のあるビューと、それらを利用するクエリを特定します。
    *   **整数線形計画法 (ILP) の実行 (`ILP` 関数):** フィルタリングされた候補に対してILPソルバー（Gurobi）を用い、現在の候補セットから最適な実体化ビューとその利用法を決定します。目的は、総利得（クエリのコスト削減益）から実体化コストを差し引いた値を最大化することです。ストレージ容量の制約やビュー間の依存関係も考慮されます。
    *   **収束判定:** ILPによって得られた解（目的関数の値）が前回の反復から改善しなくなった場合に、反復を終了します。
3.  **近傍探索なしのバージョン (`no_neighbor_search` 関数):**
    *   初期化フェーズで得られた候補セットに対して、反復的な近傍探索を行わず、一度だけILPを実行します。これは、近傍探索の効果を評価するためのベースラインとして機能します。

## 各アルゴリズムの初期化戦略

### 1. `ILP_proposed_u_b_beta.py` (利得/コスト比ベースの初期化)

*   **初期化 (`initialize`):**
    *   各サブクエリに対して、評価値として `(総利得 - 実体化コスト / サブクエリサイズ)` を計算します。ここでの「総利得」は、そのサブクエリを実体化した場合に削減できる可能性のあるコストの総和を指し、「実体化コスト」はビューを作成・維持するコスト、「サブクエリサイズ」はビューが占めるストレージサイズです。
    *   この評価値が高い順にサブクエリを選択し、全体のストレージ容量制約を満たす範囲で初期のマテリアライズドビュー候補とします。

### 2. `ILP_proposed_u_beta.py` (利得ベースの初期化)

*   **初期化 (`initialize`):**
    *   各サブクエリに対して、評価値として `(総利得 - 実体化コスト)` を計算します。
    *   この評価値が高い順にサブクエリを選択し、全体のストレージ容量制約を満たす範囲で初期のマテリアライズドビュー候補とします。

### 3. `ILP_proposed_f_beta.py` (頻度ベースの初期化)

*   **初期化 (`initialize`):**
    *   各サブクエリが、分析対象のクエリセット全体で出現する回数（頻度）を評価値とします。
    *   出現頻度が高い順にサブクエリを選択し、全体のストレージ容量制約を満たす範囲で初期のマテリアライズドビュー候補とします。

## 共通の主要関数

### `ILP` 関数 (整数線形計画問題の定義と解決)

*   **目的:** 与えられたマテリアライズドビュー候補の中から、どのビューを実体化し (`z[j]`)、各クエリがどの実体化ビューを利用するか (`y[i,j]`) を最適に決定します。
*   **入力:**
    *   `u_ij`: クエリ `i` がビュー `j` を利用した場合の利得（コスト削減量）。
    *   `x`: ビュー間の依存関係を示す行列。
    *   `M`: 各クエリ `i` が利用できる可能性のあるビュー `j` の集合。
    *   `B_max`: 利用可能な総ストレージ容量の上限。
    *   `cand_j`: 実体化候補となるビューのインデックスリスト。
    *   `cand_i`: ビューを利用する可能性のあるクエリのインデックスリスト。
    *   `b_j`: 各ビュー `j` のストレージサイズ。
    *   `m_cost`: 各ビュー `j` の実体化コスト。
*   **決定変数:**
    *   `y[i,j]`: バイナリ変数。クエリ `i` がビュー `j` を利用する場合に1、そうでなければ0。
    *   `z[j]`: バイナリ変数。ビュー `j` を実体化する場合に1、そうでなければ0。
*   **目的関数:**
    `maximize ( sum(u_ij[i][j] * y[i,j] for all i,j) - sum(z[j] * m_cost[j] for all j) )`
    つまり、ビュー利用による総利得から、実体化にかかる総コストを引いた値を最大化します。
*   **主な制約条件:**
    1.  **重複サブエクスプレッション制約:** クエリ `i` がビュー `j` を利用する場合、`j` に包含される他のビュー `u` を同時に利用することはできません（適切にモデル化されている場合）。
    2.  **利用制約:** クエリ `i` がビュー `j` を利用するためには、ビュー `j` が実体化されていなければなりません (`y[i,j] <= z[j]`)。
    3.  **ストレージ制約:** 実体化される全てのビューの総ストレージサイズは `B_max` を超えてはなりません (`sum(b_j[j] * z[j] for all j) <= B_max`)。
*   **出力:** 最適な `y_ij` と `z_j` の値、および最大化された目的関数の値。

これらのアルゴリズムは、複雑なクエリワークロードに対して効率的なマテリアライズドビュー戦略を見つけるための洗練されたアプローチを提供します。初期化戦略の違いにより、探索空間の異なる領域から最適化を開始し、最終的な解の質や計算時間に影響を与える可能性があります。
